## 1. 평가

### 1.1 리더보드 지표 — Macro F1

- 24개 검토 항목 각각에 대해 **위반(=1) 클래스의 F1 Score**를 계산하고, 24개 항목의 F1을 **단순 평균**.
- 24개 항목 모두 채점 대상 (모든 항목에 위반 사례가 포함되어 있음).
- 리더보드에는 위반 여부 열 `v1~v24`만 반영.
- 근거 문구 열 `e1~e24`는 리더보드에 반영되지 않고 **2차 평가(정성평가)용으로 보존**.

```python
# 참고 구현
from sklearn.metrics import f1_score
score = sum(f1_score(y_true[f"v{i}"], y_pred[f"v{i}"], pos_label=1) for i in range(1, 25)) / 24
```

> 항목별 양성 F1의 단순 평균이므로 **희소한 항목(위반 사례가 적은 항목)도 동일한 가중치**를 가진다. 항목별 임계/판정 기준 튜닝이 중요.

### 1.2 데이터 분할

- Public Score: 전체 테스트 데이터 **1,853건의 100%**
- Private Score: 대회 종료 시점의 Public Score와 동일
- Private 리더보드는 최종 순위가 아님 → 2차 평가·검증 후 최종 수상자 결정

### 1.3 1차 / 2차 평가

| 단계 | 내용 |
|---|---|
| 1차 | Private Score 기준 **상위 15팀** 2차 진출 |
| 2차 | 재현성 검증 + 근거 문구 정성평가 + 규칙 준수 검증 |
| 최종 점수 | **정량(1차 점수) 80% + 정성(근거 문구) 20%** → 상위 7팀 수상 |

2차 평가 세부:
1. **재현성 검증** — 제공 자료와 제출물만으로 리더보드 점수가 재현되는지. 재현 불가 시 수상 취소 가능.
2. **근거 문구 정성평가** — 정답이 위반(1)인 항목의 근거 문구(`e1~e24`)를 평가.
3. **규칙 준수 검증** — 대회 규칙 및 제출 요건 준수 여부.

### 1.4 근거 문구(e1~e24) 요구사항

- 근거 문구는 **제공 원문의 부분문자열(substring)이어야 함**. 요약·수정·생성된 문구는 자동 검증 단계에서 **무효 처리**.
- **부재탐지형 5개 항목(10·11·16·18·20번)** 은 인용할 원문이 없으므로 정성평가 대상에서 제외.

## 2. 제출 형식

### 2.1 `submit.zip` 구조

```
submit.zip
├── script.py          # 필수 — 평가 서버에서 자동 실행되는 추론 코드
├── requirements.txt   # 선택 — 추가 pip 패키지
└── model/             # 선택 — RAG 인덱스 등 정적 자산만 허용
```

- 실행 코드는 반드시 `if __name__ == '__main__':` 아래에 둘 것.
- 용량 제한: zip **2GB**, 압축 해제 후 **8GB**.

### 2.2 출력 파일 `submission.csv`

- 저장 위치: `PPS_OUTPUT_DIR`
- **49열**: `id, v1~v24, e1~e24`
- 행 수 = 입력 건수, 인코딩 **UTF-8 (BOM 없음)**
- `v1~v24`: **0 또는 1만 허용** (확률값 불가), 빈 값 불가
- `id` 중복 불가, 평가 데이터 id가 하나라도 누락되면 안 됨

### 2.3 환경 변수

| 변수 | 용도 |
|---|---|
| `PPS_DATA_DIR` | 평가 데이터 경로 |
| `PPS_OUTPUT_DIR` | 결과 저장 경로 |
| `PPS_MODEL_DIR` | 고정 LLM 가중치 경로 |
| `PPS_EMBED_DIR` | 임베딩 모델 가중치 경로 |

### 2.4 오류 분류

| 오류 | 원인 | 일일 제출 횟수 차감 |
|---|---|---|
| 설치 오류 | zip 구조 불일치, 패키지 설치 실패 | ✗ 미반영 |
| 제출 오류 | `script.py` 실행 오류, 시간 초과 | ✓ 반영 |

## 4. 대회 규칙

### 4.1 참가 / 제출

- 개인 또는 팀 참가, **팀 최대 5명**, 동일인 중복 등록 불가 (팀 병합 마감 09.23)
- **1일 최대 제출 1회**
- 사용 언어: Python / 모든 csv는 UTF-8

### 4.2 고정 LLM 기반 파이프라인

- 지정된 고정 LLM 위에 전처리·프롬프트 구성·검색(RAG)·후처리 등 **추론 파이프라인을 개발**하는 대회.
- 두 모델은 평가 서버에 준비되어 있음 → **모델 제출 불필요, 제출해서도 안 됨**.
- ❌ 파인튜닝 금지 (LoRA·QLoRA 등 어댑터 학습 포함), 가중치·어댑터 제출/로드 금지.
- ❌ 고정 LLM·임베딩 모델 외에 **참가자가 학습시킨 모델 가중치를 판정에 사용 금지**.
- `model/`에는 RAG 검색 인덱스 등 **정적 자산만** 포함 가능.
- ✅ **각 공고마다 고정 LLM 정상 호출 1회 이상 필수** — "정상 호출"은 해당 공고 내용을 포함한 프롬프트로 호출해 정상 응답을 받는 것. 호출이 없거나 공고와 무관한 호출만 있으면 무효 처리될 수 있음.
- ✅ 모델 출력에 대한 후처리·규칙 기반 보정은 자유.
- ✅ 로컬 개발 환경(GPU·런타임·정밀도)은 자유.

### 4.3 데이터 사용 — 외부 데이터 금지, 자가 라벨링 허용

**✅ 허용**
- 대회 제공 데이터(무라벨 20,000건, dev 200건, `data/` 폴더)를 학습·검증·검색·후처리 등 어떤 용도로든 사용.
- **자가 라벨링 전면 허용** — 방법(수작업·규칙 기반·모델 기반) 제한 없음.
- **라벨 생성 단계에 한해 외부 LLM(상용 API 포함) 사용 허용** — 단, 외부 LLM에는 대회 제공 자료만 입력.
- 공개 오픈소스 라이브러리 사용 (`requirements.txt`로 pip 설치).
- 대회 코드 공유 게시판에 **전체 공개**된 참가자 생성 자료(라벨·가공 데이터 등) 활용.

**❌ 금지**
- 나라장터·공공데이터 API·웹 크롤링 등 외부 경로로 공고 원문·메타데이터·라벨·정답성 정보를 추가 수집·활용.
- 배포 자료를 공개 원문과 대조해 **익명화된 식별자(기관명·공고번호 등) 복원**.
- 외부 LLM의 웹 검색·외부 문서 결합 기능으로 원문 조회·외부 데이터 취득.
- **제출 추론 코드에서 외부 LLM·외부 API 호출**.
- 제공 자료 외 데이터 자산(공고·법령·라벨 등)을 pip 패키지 동봉, `model/` 동봉 등 **우회 경로로 반입** (라이브러리에 데이터 동봉 포함).
- 자가 생성 라벨·가공 데이터의 **팀 간 사적 공유** (공유는 코드 공유 게시판 전체 공개만 허용).

**법령 기준**
- 판정 기준은 배포된 **법령 패키지 스냅샷**(법령·행정규칙 전문 및 중소벤처기업부 고시 제2025-96호)으로 고정.
- 대회 기간 중 법령 개정은 반영하지 않음. 파이프라인에 결합하는 법령 자료도 배포 패키지를 사용해야 함.

### 4.4 재현 가능성 및 출처 명시

- 수상팀 결과물은 **대회 제공 자료 + 제출 자료만으로 재현 가능**해야 함 (불가 시 수상 취소 가능).
- 자가 라벨링 사용 시 라벨 생성 코드·프롬프트·절차도 재현 대상.
- 외부 LLM으로 만든 라벨은 생성 코드·프롬프트·사용 모델(버전) 기록 + 생성된 라벨 데이터 제출로 재현을 갈음. (상용 API 비결정성에 의한 출력 차이는 문제 삼지 않음)
- 결과물 산출에 사용된 모든 요소의 출처를 명확히 기술할 수 있어야 함.

### 4.5 평가 데이터 사용 제한

- ❌ 비공개 평가 데이터를 이용한 추가 학습·모델 튜닝·Pseudo-Labeling 등 모델/규칙 갱신 금지.
