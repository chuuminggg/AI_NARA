## #7 대비 변경점 — 모델 입력 발췌 (FOCUS_MODE)
- **문제:** `build_context`는 공고문부터 문서 순서대로 16,000자를 채우고, 넘치는 뒤쪽 문서(규격서·과업지시서·제안요청서)를 통째로 뺀다. 무라벨 2,000건 중 50.1%가 첨부 일부를 잃는다(총 길이 중앙값 16,260자).
- **변경:** 모델 질의(그룹 모드)에서만 발췌 입력을 쓴다. 규칙·게이트·근거 검증은 전과 같이 원문 전체를 본다.
  - 예산의 55%는 기존처럼 문서 순서대로 채운다.
  - 나머지 45%는 빠진 구간에서 모델 판정 항목 단서(모델명·제조사·상표·동등, 참가자격, 기업규모, 직접생산·경쟁제품, 소프트웨어·대기업, 판로·우선조달, 대문자+숫자 모델 표기) 주변(앞 200·뒤 400자)을 원문 그대로 발췌한다.
- 모델 질의 항목에서 v24를 뺐다(v9·v10·v15·v17·v20). v24는 규칙 대체라 모델 답을 쓰지 않았다. 출력이 짧아지고 남은 항목에 집중한다.
- 모델 판정 기준 보강:
  - v10: 행사기획·디자인·SW 유지보수 같은 용역도 경쟁제품일 수 있음(dev v10 양성 7건 모두 용역).
  - v20: 상호출자제한기업집단, 사업금액 20억·40억·80억 구간별 참여제한 문구(대회 설명회 항목 설명).
- 입력 길이 상한은 같다(16,000자, 토큰 예산 초과 시 기존 축소 로직). 실행 시간은 #7과 같은 수준으로 본다.

## 검증
- 무라벨 1,500건 중 16,200자 초과 공고:
  - 모델 표기(v9 단서)가 입력에 보이는 공고: 14/84 → **82/84**
  - 기업규모 제한 문구: 442/462 → 461/462
- dev: 정답 근거 문구가 입력에 보이는 비율 53/54 → 53/54. dev 공고는 첨부가 잘리는 경우가 드물어 차이가 없다.
- T1~T7 #7과 같음(규칙 경로 변경 없음), mock·zip PASS, 실제 문항표로 무라벨 500건 메시지 생성 확인.
- **모델 출력이 바뀌는 변경이라 GPU 실측이 없다.** 보정 시뮬레이션(0.772)으로는 효과를 잴 수 없다.

- 검토 후 넣지 않은 것: 모델 근거 문구의 항목 단서 필터. dev 정답 근거가 빈칸이거나 단서 패턴 밖인 경우(DEV-23 `DJI Matrice 4E/T`)가 있어 정답 양성을 지운다.
